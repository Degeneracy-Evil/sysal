基线：Sysal C++20；SystemCard 最低 Python 3.6.8 / glibc 2.17，开发工具 Python 3.12。
PyPI 正式发布等待账号配置，不属于本轮七项开发的发布动作。

## 开发约束

- I/O 和动态库调用留在 Reader；Parser / Resolver 可通过 RawStore 完全离线验证。
- SystemCard 只消费 Sysal 公共 API 和固定版本、SHA-256 的发布包。
- 新增公共字段的语义先给用户选择，未知信息与资源无限制须明确定义。
- 后端没有安装或硬件不存在时，不导致完整采集失败；不把未经验证的模拟结果当作真实硬件验证。
- 开发期间优先构建与真实运行，不逐项扩展单元测试；仅保留约定的展示快照，并在最终交付核对兼容构建与安装链路。

## 交付顺序

优先修正资源可见性，再实现配额和按域采集。新增后端与固定快照测试随后完成，
最后同步文档与启动入口并验证新 Sysal 发布包在 SystemCard 中的完整消费链路。

## 当前交付说明

- NVIDIA A100 实机验证：空值与 -1 为零可见，单 GPU UUID 仅保留对应设备。
- cgroup v2 实际容器：--cpus=1.5、--memory=512m 返回 150000/100000 微秒与 536870912 字节。
- SystemCard 实际栏目采集：system 的位掩码为1，memory 为261，accelerators 为329。
- 固定展示数据涵盖容器 CPU/内存限制和 MIG；四份终端快照可直接审阅。
- 启动脚本实际验证：uvx 使用 Python 3.12 wheel；临时 venv 使用 CentOS 7 的 Python 3.6.8 wheel，展示真实的1.5 CPU / 512 MiB 配额。
- Sysal 0.0.9 引入公共字段，SystemCard 持续固定相应兼容包的版本和 SHA-256。
- CentOS 7/GCC 构建通过，动态库最高 GLIBC 需求为2.14，支持目标为2.17+。

“已实现”指七项代码与文档已交付，不表示所有硬件平台都经过实机验收。
当前没有 AMD、Intel 或启用 MIG 的设备；这些后端的真实硬件验证仍需对应环境。
cgroup v1 已实现但当前宿主机为 v2；复杂 SYCL 子设备 selector 仍为明确边界。
PyPI 首次发布继续等待账号配置，bootstrap 暂可使用本地 wheel。
